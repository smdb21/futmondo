# Saved page per account

`page_preferences.R` persists the last visited main application page under the authenticated Futmondo `userid`. The preference applies across browsers, leagues and new Shiny sessions, including remembered login. Login is excluded. New, unknown or unauthorized saved pages open Today's market; Admin is restored only after the existing server authorization check.

`fm_saved_pages(is_admin)` defines the allowlist. `fm_page_store(user_id, page = NULL, visited_at = NULL, owner)` asynchronously reads one row or upserts `user_id`, `page` and the UTC visit timestamp through the existing bounded HTTP transport, with an eight-second timeout. Only server credentials access the table; no password, authentication token, response body or league data is stored. Database `recorded_at` records persistence time. An update trigger rejects older visits arriving from concurrent sessions. The account/page data has no expiry.

`fm_page_preferences(session, login_token, page, is_admin, store)` binds authentication and navigation. Its `initial` reactive selects the saved item when the dynamic sidebar is rendered; the unconditional Today redirect is removed. Restoration and repeated selection add no writes. There is one read per account login and at most one in-flight write per session, coalescing further changes to the latest visit. Active saves may finish after logout/session closure using the captured account ID. Late reads cannot override manual navigation or a different login. Failed/unacknowledged writes retain the latest pending page for Retry or subsequent navigation; a closed process cannot retain an unsaved failure. Read failures open Today with visible Retry feedback. There is no polling or worker.

Apply `scripts/migrations/20261107050308_user_page_preferences.sql` to existing databases. New databases include the same objects in `scripts/schema.sql`. RLS is enabled, public/browser roles have no privileges or policies, and `service_role` has only SELECT/INSERT/UPDATE. The trigger uses SECURITY INVOKER and an empty search path. The configured hosted database received the migration and corrected account-ID constraint on 2026-11-06 (Pacific time).
