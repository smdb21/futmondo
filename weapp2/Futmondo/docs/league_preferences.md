# Football league scope and last selected league

`competition_context.R` defines `fm_basketball_sport(sport)`, `fm_supported_leagues(championships, leagues)` and `fm_filter_league_answer(answer)`. Only authoritative `sport` fields identify basketball (`basket`, `basketball`, `baloncesto`), including a matching competition object. Unknown sports remain unknown; names never infer sport. Filtering preserves source timestamps and other response metadata. Active source parsing, existing cache returns, metadata normalization, worker snapshot restoration and the selector all enforce this scope. Python applies the same rule before storing active-league HTTP checkpoints and when replaying older checkpoints. Supported resources continue using durable database snapshots and retain their original source age.

`league_preferences.R` adds an independent account-wide preference. `fm_league_store(user_id, championship_id = NULL, selected_at = NULL, owner)` asynchronously reads one row or upserts `{user_id, championship_id, selected_at}` with server credentials and an eight-second timeout. It uses `user_league_preferences`; no token, password, private response or background session is stored. The table is server-only with RLS. The database rejects older concurrent selections and references an existing, unblocked league.

`fm_league_preferences(session, login_token, leagues, store)` returns a `selected` reactive. It loads once per account login; source reads for a default league wait for that result. An available saved league wins over response ordering. An unavailable/blocked saved league falls back to a valid league and persists that fallback; an account without a preference also saves its initial valid league. A failed preference read shows Retry and does not overwrite an unknown saved preference with the fallback. Manual choices save immediately, with at most one in-flight write and one coalesced latest pending selection. Unacknowledged writes stay retryable. Late reads cannot override a manual change or another account. Valid restoration adds no write; there is no polling. Pending failed writes are not durable until acknowledged, and do not survive process loss. In-flight account-scoped writes may finish after logout.

`server.R` uses the restored selection for both the dropdown and league/team resource context, preventing initial requests for another league. `ui.R` adds mobile-safe retry feedback beside the selector. Existing page navigation preferences remain independent. Worker status also clears an old failure when a recovered job reports no error without changing its saved payload version.

## Database policy and approved cleanup

Apply `scripts/migrations/20261112024500_football_leagues_and_selection.sql` before deploying the new application. Fresh databases include the same objects in `scripts/schema.sql`. The migration creates preference storage and minimal server-only `blocked_leagues` ID/sport tombstones. It blocks catalog/observation reinsertion and queue admission, claim, lease continuation and verified membership for known basketball IDs. Blocking is separate from deletion and preserves existing records until cleanup is explicitly approved. New source-identified basketball IDs are also blocked at catalog insertion.

`scripts/purge_basketball_leagues.sql` is a separate, explicitly approved permanent cleanup, never run by startup or the block-only migration. It uses a fixed allowlist of existing league-scoped factual tables, removes blocked jobs/snapshots/chunks/checkpoints and invalidates affected account-level discovery snapshots. It deletes league-owned observations before teams and championships, preserving football observations, account access, Futmondo membership, tokens and shared global player/club catalogs. Shared global records are not assigned a sport without evidence. Minimal blocked identifiers remain to prevent reinsertion.

## Market worker compatibility

The football market parser returns a canonical `data.table`/`data.frame`. The worker codec previously rejected that class before publication, causing the reported `resource_parse`. `fm_worker_encode` now converts that exact class to a plain factual frame, dropping process-local internal pointers. Unknown subclasses remain rejected. Zero/negative/unknown values, row order and source metadata retain their meaning. Real helper checks retrieve a synthetic market, persist/restore it and reuse its response checkpoint after helper restart with one HTTP request total.

## Verification and performance

Focused checks cover sport evidence/unknowns, preference account/session isolation, delayed/manual races, coalesced saves, failed acknowledgements, timestamped REST payloads, old checkpoint filtering, market persistence/replay, strict codec classes and recovered statuses. The isolated SQL rehearsal distinguishes block-only preservation from approved cleanup, preserves exact football records/shared players, prevents reinsertion, rejects stale/blocked selections and denies browser access. The offline lifecycle exercises startup and all eight tabs without real HTTP or database mutations. Actual results are in `data_review_results.md`.

There is one extra asynchronous database read per login and bounded writes only when the effective selection changes; valid restore/ordinary refresh adds no write. Preference loading holds only dependent league reads, leaving the event loop responsive. Existing source/database resource reuse remains intact. Sport filtering handles small source league lists, Python builds one competition lookup, and no timer, worker, scheduled acquisition or transaction behavior is added. Policy checks use the blocked-league primary key; 1,000 guarded synthetic history inserts took 54.3 ms locally. The 5,001-row saved-ledger restore took 0.141 s. Neither measure establishes hosted throughput or VM sizing. The market conversion runs in the existing private R helper within existing row/byte limits. No dependencies or environment variables are added; source/manifest changes require the usual application rebuild/redeployment.
