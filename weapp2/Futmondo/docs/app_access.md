# Application access switch

Admin → App access exposes **Block non-admin access**, enabled by default. Disabling it admits authenticated Futmondo users. The existing server-side `is_authorized_admin()` identity check (`admin` environment variable, trimmed/case-insensitive) always permits administrators to enter and manage the setting. Browser-supplied account names alone never grant admission: the check uses the successful Futmondo authentication result.

`app_access.R` provides:

- `fm_access_store(blocked = NULL, token = NULL, owner = "")`: asynchronous singleton read or admin-authorized upsert through the existing server-only Supabase REST transport. Reads select one boolean; writes require the returned boolean to match. Missing/malformed rows, failed requests and unconfirmed writes are errors.
- `fm_app_access(token, owner = "", store = fm_access_store)`: administrators bypass the read; non-admins require an explicit stored `FALSE`. No process-memory policy cache can keep a previously open state alive across a failed read.
- `fm_admin_access(session, login_token, active, store = fm_access_store)`: loads on Admin activation, renders the accessible switch, and saves explicit changes. The switch is disabled while loading/saving. Failed or uncertain saves require Reload to verify the database before another change. Writes independently recheck the configured administrator identity.

Both password admission and remembered-token restoration await the access check before exposing the application login token, account identity or startup resources. Policy denial and storage failure have different feedback. Logout/account-switch/session-close generation guards discard late results. `remember_login_session()` now awaits a synchronous or promised restore callback; explicit `FALSE` returns `blocked` without activating the remembered session or its expiry timer. Cookies may remain stored and can restore only once app access is allowed again.

Admitted non-admin sessions perform one serialized asynchronous policy read two minutes after admission and on subsequent two-minute session ticks (skipping ticks while a read is in flight). Enabling the switch signs them out at the next completed check; request/queue latency adds to that interval. A failed read also signs them out. Administrators and signed-out sessions do not poll. A closed/denied session cancels its timer and ignores late completions. The initial admission read cannot reuse an old open result.

`public.application_access` contains exactly one permitted identity (`id = 'main'`), `admin_only BOOLEAN NOT NULL DEFAULT TRUE`, and `updated_at`. The migration seeds the enabled value. RLS is enabled with no browser policies; `anon`, `authenticated` and PUBLIC receive no privileges, and only `service_role` receives SELECT/INSERT/UPDATE. The secret stays on the R server. Factual-table resets exclude this setting. Apply the migration before deploying the runtime; missing storage blocks non-admin admission while administrators can still enter to diagnose it.

Performance: one small indexed read per non-admin admission, then at most one read every two minutes per idle active non-admin session (plus transport time). Admin loads add one read per activation/reload and one upsert per actual change; unchanged input events perform no write. Requests have an eight-second transport timeout, execute asynchronously, and hold bounded per-session state. There are no Futmondo calls added to policy checks, source-data scans, dependencies, page-wide redraws or persistent authentication secrets in this table.
